Issue body

the X to close project should be brighter, same as other symbols next to it (the todo icon and the github icon). it's currently too dark against the background and its just generally bad practice. also, perhaps we can change the icon to an x in a circle, the other icons are also circular so that would look nice.

Chosen approach

Replace the &times; HTML entity in the remove button with an inline SVG x-circle icon (feather-style: 14×14px, stroke="currentColor", circle + two diagonal lines), stored as a local constant SVG_X_CIRCLE in renderer/sidebar.js alongside the existing SVG_TODO and SVG_GITHUB constants. Update the .remove-btn CSS to raise opacity at rest from 0.15 to 0.5 and change colour from #555 to #666, matching the .project-section-link scheme. Keep the red hover tint — it signals a destructive action and is intentional UX. No changes to IPC, state, or any other file.

Assumptions

  • The red hover tint (color: #e55; background: #2a1515) on the close button is intentional and should be preserved — it visually distinguishes a destructive action from navigation actions.
  • 14×14px is the correct icon size — all neighbouring icons use this size.
  • Padding should change from 2px 6px to 4px to align with .project-section-link sizing and give the circular SVG equal spacing on all sides.
  • The feather/lucide x-circle path (circle cx="12" cy="12" r="10" + two diagonal lines) is an appropriate "x in a circle" — the same icon family used for SVG_TODO.

Definition of done

  • The remove-project button renders an SVG circle with an X inside (not a plain &times; character).
  • The icon is visible at opacity: 0.5 when the project row is hovered (not nearly invisible at 0.15).
  • On button hover, the icon turns red (#e55) on a dark background — same destructive-action treatment as before.
  • The SVG scales and colours correctly alongside the TODO and GitHub icons (same 14×14px size, same currentColor approach).
  • No other sidebar elements are visually changed.
  • npm test passes.

Up-front tests

  • test/sidebar.test.js::remove-btn renders SVG not times entity — asserts that renderProjects output contains <svg inside the .remove-btn and does not contain &times;.
  • test/sidebar.test.js::remove-btn SVG has circle and x lines — asserts the SVG contains a <circle element and two <line elements.

Decisions

Don'ts / rejected approaches

Don't move SVG_X_CIRCLE to utils.js — SVG_TODO and SVG_GITHUB are already defined locally in sidebar.js; this icon is used only there; YAGNI.
Don't use a CSS-only circle via border-radius: 50% — the &times; entity doesn't scale cleanly at 14px and won't inherit currentColor the same way.
